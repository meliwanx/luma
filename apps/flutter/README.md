# Luma Flutter client

Luma is a personal assistant client for Android, iOS, macOS, Windows, Linux, and the web. Your data stays on the server you deploy. The client uses the built-in username/email and password account system. Registration and optional invite codes follow the server's `/api/v1/auth/config` settings.

## Development

Install Flutter and add its `bin` directory to `PATH`. Use the SDK version required by `pubspec.yaml`, then run:

```sh
flutter pub get
flutter run -d <device> --dart-define=API_BASE_URL=http://localhost:8000
```

Debug builds default to `http://localhost:8000`. On a physical phone, provide a server address reachable from that phone. Release builds require an explicit `API_BASE_URL`; an unconfigured build shows a setup message. Use HTTPS for a remote deployment. Account session tokens are stored with `flutter_secure_storage`; account passwords are never persisted.

You can also provide build settings from a file:

```sh
flutter run -d <device> --dart-define-from-file=dart_defines.example.json
```

Android reads `flutter.sdk` (and `sdk.dir` for the Android SDK) from `android/local.properties`. This local file is generated by Flutter and should not be committed.

## Account settings

Settings includes profile editing, password changes, login device management, and account deletion. Password changes revoke other devices. Deletion requires the current password and a separate confirmation, and removes all account data permanently.

WebView remains available for document previews and the isolated browser workspace. Authentication uses native forms.

## Validation

```sh
flutter pub get
flutter analyze
flutter test
python3 -m unittest discover -s scripts/tests
```

If your checkout path contains non-ASCII characters, validate and build from an ASCII temporary copy. Copy source fixes back without generated files or local SDK paths.

## Packaging and iOS signing

```sh
flutter build apk --release --dart-define=API_BASE_URL=https://luma.example.com
flutter build macos --release --dart-define=API_BASE_URL=https://luma.example.com
API_BASE_URL=https://luma.example.com BUILD_NUMBER=2 ./scripts/build_ios_release.sh
```

The iOS bundle identifier is `com.example.luma` (`com.example.luma.RunnerTests` for tests). Before packaging a signed IPA, set your own unique bundle identifier, select your Apple development team in Xcode, and replace `YOUR_TEAM_ID` in `ios/ExportOptions.plist`. The repository contains no signing identity or development team. Install your signing certificate and provisioning profile in your local or CI keychain and keep signing credentials outside the source tree. The release script discovers `flutter` from `PATH` and uses the version in `pubspec.yaml`; `BUILD_NUMBER` optionally overrides its build number.

For an unsigned iOS build:

```sh
flutter build ios --release --no-codesign --dart-define=API_BASE_URL=https://luma.example.com
```
